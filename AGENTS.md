# AGENTS.md — l2start-server

Инструкция для ИИ-агентов (Cursor и др.). Глеб пишет и читает **по-русски**: отчёты, планы и вопросы — на русском, коротко.

## Что это

Сервер Lineage 2 **Interlude** на базе **L2J Mobius CT_0** (`core/`, сток, импорт фиксирован в `upstream.lock`)
плюс своя **платформа модулей** (`platform/`) и модули (`modules/`):
- платформа: загрузка модулей (`module.json`), конфиг-слои, миграции SQL, данные (NPC/спавны/html/мультиселлы),
  события, команды, сервисы, guard/circuit breaker; ядро вызывает её только через помеченные хуки;
- боты (`bots-core`, `bots-brain-basic`): персонажи без клиента, «как игроки»; **директор присутствия** держит
  нужное число ботов в мире у живых игроков; мозги, пати с игроком (фаза 6);
- экономика (`economy-market`): боты-торговцы, рынок, WTS/WTB, трейд с ботом;
- `rates-floating` (рейты x10 плавающим дропом), `world-info` (уровни в телепортах), `town-buffer` (платные
  бафферы-боты), `starter-kit`, `lw-fixes`.

Профили: `solo` (Глеб играет один, с ботами) и `online` (без ботов).

## Структура репозитория

| Путь | Что |
|---|---|
| `core/` | Mobius CT_0 (java + `dist/game/data`). Менять только хуками (см. ниже) |
| `platform/` | платформа модулей: `api/` (контракт для модулей), `runtime/`, `hooks/` (`CoreHooks` — точки входа из ядра), тесты |
| `platform/test/fixtures/modules/` | тестовые модули `fx-*` — только для smoke |
| `modules/<id>/` | модули: `module.json`, `src/`, `test/`, `data/`, `sql/`, `MODULE.md`; список — `modules/README.md` |
| `docker/` | compose, `entrypoint.sh`, профили, оверрайды конфигов `docker/overrides/{solo,online}/game/config/**` |
| `tools/` | `check-hooks.sh`, `smoke.sh`, `hook-report.sh`, проверка апстрима и геодаты |
| `docs/` | архитектура, API, хуки, планы фаз |
| `build.xml` | Ant: ядро + платформа + модули (2-й проход — модули, зависящие от `bots-core`) |

## Жёсткие правила

1. **`core/` — только помеченными хуками.** В ядре можно только *добавлять* строки, каждая помечена
   `// [HOOK:ID]` или внутри блока `// >>> [HOOK:ID]` … `// <<< [HOOK:ID]`. Каждый ID описан в
   `docs/PLATFORM_HOOKS.md`. `tools/check-hooks.sh --worktree` обязан проходить (его же гоняет CI).
   Логика хука — в `platform/.../hooks/CoreHooks.java`, без слушателей хук инертен (сток).
2. **Фичи — модулями** в `modules/`, через API платформы (`docs/PLATFORM_API.md`, текущая версия 1.7.0).
   Новое в API — default-метод «Since API x.y», поднять `Platform.API_VERSION` и `platform` в `module.json`.
3. **ID-диапазоны** NPC/мультиселлов/байлистов — блоками по 100 из 95100–99999, запись в `docs/ID_RANGES.md`
   и `reserves` модуля.
4. **Предметы ботов существуют только пока бот в мире**; вне мира — учёт «на бумаге». Не создавать реальных
   предметов/адены ботам вне этой схемы (сумки торговцев чистятся).
5. **Трейд с ботом — только через путь P6-BOT-TRADE** (`ctx.onBotTradeRequest`), как в `economy-market`
   (`Meetings.exchange`) и `town-buffer`: бот подтверждает последним, проверка содержимого обоих окон под
   замком обоих `TradeList`, затем проверка результата. Никаких прямых переносов предметов.
6. **Рейты — через `rates-floating`** (доп. стоковые роллы, хук `P7-DROP-FLOAT`). Стоковые множители шанса
   (`DropChance*`, `ChampionRewardsChance` и т. п.) держать = 1: иначе ломаются группы дропа Mobius.
7. `git config core.autocrlf false`. Файлы ядра — CRLF, остальное в основном LF; при правке сохранять концы строк.
8. **Коммит на шаг** (E1, E2…, R1…), понятное сообщение.
9. **Никогда не мёржить PR без явного согласия Глеба.** PR — драфтами.
10. **Новые этапы — сначала план** `docs/<NAME>_PLAN.md` (что, шаги, дни, КТ, вопросы), согласование с Глебом,
    потом код. После реализации — обновить план (ответы, «Сделано», отличия).
11. Ничего не отправлять/не публиковать от имени Глеба без его просьбы.

## Сборка и тесты

```bash
ant test                      # ядро + платформа + модули + JUnit 5 (после смены ветки: rm -rf build/test-classes build/module-classes build/dist/game/modules)
tools/check-hooks.sh --worktree   # правило хуков
tools/smoke.sh                # полный docker smoke (~10 мин) — только перед КТ / по просьбе
```

- CI (GitHub Actions): unit tests, check-hooks, Ant build, Docker image, Docker smoke.
- Запуск сервера — Docker на ПК Глеба: `start.bat solo rebuild` (или `online`). **Пересобирает и перезапускает
  Глеб сам**; агент только говорит, какую ветку.
- Логи модулей: `Module[<id>]: ...`; админ-команды: `//module`, `//bots`, `//market`, `//rates`.
