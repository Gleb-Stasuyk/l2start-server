## 1. Чемпионы

Сток: `ChampionEnable`, `ChampionFrequency` (%), `ChampionMinLevel/MaxLevel`, `ChampionHp`, `ChampionHpRegen`, `ChampionAtk`, `ChampionSpdAtk`, `ChampionRewardsExpSp`, `ChampionRewardsChance/Amount`, `ChampionAdenasRewardsChance/Amount`, `ChampionRewardItems` + шансы для ниже/выше уровня, `ChampionAura`, `ChampionTitle`, `ChampionPassive`.

**Важно:** `ChampionRewardsChance ≠ 1` в стоке ломает логику групп дропа (тот же `rateChance ≠ 1`, что в RATES_PLAN §1.3). Поэтому шанс/количество/адену чемпиона делает `rates-floating`, а в ini — 1.

Предлагаю (`docker/overrides/{solo,online}/game/config/Custom/ChampionMonsters.ini`):

| Ключ | Значение | Почему |
|---|---|---|
| `ChampionEnable` | True | |
| `ChampionFrequency` | **3** | ~1 из 33 мобов; при x10 опыта встречается часто, но не каждые 2 минуты |
| `ChampionMinLevel` / `MaxLevel` | **15 / 75** | просьба Глеба; 76+ — эндгейм без чемпионов |
| `ChampionHp` | **6** | при x10 мобы и так «тают», 8 — затянуто |
| `ChampionHpRegen` | 1.5 | |
| `ChampionAtk` / `ChampionSpdAtk` | **1.5 / 1.2** | реальная опасность для соло на своём уровне |
| `ChampionRewardsExpSp` | **4** | итого x40 к стоку (сверх x10 рейтов) |
| `ChampionRewardsChance` / `Amount` | **1 / 1** | делает модуль |
| `ChampionAdenasRewardsChance` / `Amount` | **1 / 1** | делает модуль |
| `ChampionRewardItems` | пусто (вопрос 2) | сток: 6393 (Glittering Medal, ивентовая) |
| `ChampionAura` / `ChampionTitle` | True / Champion | |
| `ChampionPassive` | False | |

**В `rates-floating`** (новые ключи): `ChampionChance = 2` (шанс вещей чемпиона = 3 × F × 2, доп. роллов до 6), `ChampionAdena = 3` (адена x5 × 3 = x15, ровно), количества стакающихся x1..x3 как у всех. Пример: 30 ур. на ровном чемпионе — C = 3 × 1,35 × 2 ≈ 8 (обычный моб — 4).

**Боты:** охотники бьют чемпиона только если уровень ≥ моба и HP-класс «танк/пати» (иначе обходят), сопартийцы — по команде игрока; правка выбора цели в `bots-brain-basic` (~0,5 дня). Директор ботов не меняется.

## 2. Shift+клик — дроп и спойл

`NPC.ini: AltGameViewNpc = True` (solo и online): игрок видит окно статов и кнопки дропа/спойла (`NpcViewMod`). Но сток показывает шансы со стоковыми множителями (x1), наши доп. роллы и x1..x3 не видны.

`rates-floating` регистрирует свой бипас-обработчик `NpcViewMod` (после стокового — заменяет его, без хука; если реестр не позволяет замену — хук-строка в `NpcViewMod`): те же окна, но
- шанс вещи = 1 − (1 − p)^C, где C — шанс смотрящего (его уровень, пати, разница с мобом; чемпион ×2, рейд ×2, эпик сток);
- количество: стакающиеся `min–max×3`, «ровно 1» — 1, адена `min×5–max×5` (чемпион ×15);
- строка сверху: `F = 1,20 (уровень 1,2 × разница 1,0), шанс x3,6`.

## 3. Титул: уровень и агрессия

`NPC.ini: ShowNpcLevel = True`, `ShowNpcAggression = True` (оба профиля). Вид: `Lv 25 [A]`, `[G]` — моб зовёт своих; чемпион `Champion Lv 25 [A]`. Кода нет. Ботам не мешает (титулы игроков не трогаются).

## 4. Уровни мобов в телепортах

Сток строит список из `data/teleporters/**` (`<location name="Cruma Marshlands" .../>`), имена в XML. Нужен вид `Cruma Marshlands (21-27)`.

- **Хук `P8-DATA-TELEPORT`** (1 строка после загрузки `TeleporterData`): модуль может поменять имена точек.
- **Модуль `world-info`** (данные + код): для каждой точки «охотничьей зоны» берёт спавны монстров в радиусе 4000 от точки назначения, диапазон уровней = 10-й…90-й перцентиль (без рейдов/квестовых), округление; точки в городах, у замков и стоимостью в предметах не трогаются. Ручные правки — `data/teleport-levels.xml` (`<loc name="Cruma Tower" levels="40-52"/>`). Лог: `teleports: 214 locations, 131 with levels`.
- Те же диапазоны можно отдавать ботам (`bots-core` WorldCatalog уже знает зоны) — не обязательно.

## 5. Бафер в Дионе (платный, адена)

Сток Mobius: Scheme Buffer — NPC 50008, HTML `html/mods/SchemeBuffer/*`, список `SchemeBufferSkills.xml` (категории Buffs/Dances/Songs/Chants/Special/Resist + группы MAGE_GROUP/FIGHTER_GROUP, цена на баф), `SchemeBuffer.ini` (`BufferItemId = 57`, `BufferStaticCostPerBuff`, `BufferMaxSchemesPerChar = 4`), схемы игрока. Не заспавнен.

Предлагаю **модуль `town-buffer`**:
- спавн NPC 50008 в Дионе — там, где был на x100 (15569, 142884, -2704); имя/титул «бафер» (вопрос 4: только Дион или все города);
- цены — данные модуля (тот же формат), за адену, **по уровню игрока**: цена × 0,25 до 20 ур. → ×1 на 40 → ×1,5 на 76 (линейно); базово: баф пророка/эльфа/орка 1 000, танец/песня 2 000, чант 1 500, особые (Prophecy of Fire/Water/Wind, Chant of Victory, Magnus) 10 000, резисты 1 000, группа (MAGE/FIGHTER) = сумма − 20 %. Полный набор воина на 40 ур. ≈ 35 000 (≈ 8 % часа фарма при x5), на 20 ур. ≈ 9 000;
- длительность: стоковая (20 мин/2 мин песни), или 1 час как на x100 — нужна маленькая правка (вопрос 3);
- в `online` тоже (плата за адену — сток механики), бафер не работает на PK/в бою, как в стоке;
- «бафер-бот» (живой персонаж бота, продающий бафы стоковым `SellBuffs`) — вариант на потом, после фазы 6.

**Экономика:** адена от бафера уходит из мира (сток адены), это кстати при x5; `economy-market` не меняется. Боты-охотники бафер не используют (у них свои баф-скиллы).
