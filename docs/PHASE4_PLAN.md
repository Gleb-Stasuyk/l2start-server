## 0. Коротко

- **Цель этапа:** бот, которого игрок видит вблизи, ведёт себя как живой игрок своего класса. Он пьёт банки и не умирает глупо, носит свои бафы, дерётся по роли (лучник держит дистанцию, маг бьёт по слабости и отходит, кинжальщик заходит со спины, хилер лечится). Между охотами он живёт: ходит в город за покупками, стоит AFK, садится отдохнуть, выходит из игры «по-человечески». Растёт в уровне и одевается по своему расписанию.
- **Философия не меняется:** боты — иллюзия вокруг живых игроков. Подробное поведение включается только рядом с игроком (LOD **ACTIVE**, ближе 3000). Дальше бот живёт по упрощённой схеме, как сейчас, а вне поля зрения его нет вовсе: режиссёр выводит его, а уровень и вещи растут «на бумаге». Поэтому сложный бой почти ничего не стоит по нагрузке: одновременно в ACTIVE бывают десятки ботов, а не тысяча.
- **Шаги:** 4a выживание, боевое API и кайт лучников и магов → мини-проверка → 4b бафы → 4c бой по ролям → **КТ7** → 4d жизнь между охотами → 4e расписания, рост, экипировка → 4f хвосты 3f → 4g пары ботов → 4h документация и мёрж → **КТ8**.
- **Объём:** около 25–30 рабочих дней агента плюс 2–4 дня на правки по твоим КТ. Это размер **L** по дорожной карте.
- **Ядро Mobius не трогаем.** Если какой-то механике понадобится новый хук (сейчас их 12), согласую отдельно. По предварительной оценке, всё делается через существующие хуки и API модулей.
- **Уже решено:** рейты x1; профиль `online` близок к ванили, боты там выключены до этапа VPS; ответ игроку с PvP-флагом уже есть (`PvpFightBack`, этап 3f).

## 1. Что берём из готового кода (проверено по исходникам)

| Откуда | Что | Как используем |
|---|---|---|

Механику (дальность, MP, откат) берут из самого скилла. | **Главная основа 4c.** Формат и словарь условий переносим почти один в один в свой `data/playstyles.xml` модуля мозга. | LW `managers/PhantomCasterPositioning.java` (+ тест) | Выбор точки для стрелка или мага: на дистанции скилла, с прямой видимостью, с обходом по геодате (веер 0/±30/±60°). | Кайт лучников и магов — уже в 4a (просьба Глеба), настройка по ролям в 4c (интерфейс `Geometry` ложится на наш `geo()`). |
| LW `managers/PhantomChargePlanner.java` | Накопить заряды или потратить их (Gladiator, Tyrant). | Условия `CHARGES` / `CHARGES_BELOW` в плейстайлах. |
| LW `managers/PhantomClassRecovery.java` | Восстанавливающие скиллы класса (441, 417) — только в безопасный момент, не в бою. | Отдых в 4a/4d. |
| LW `managers/PhantomBuffs.java` | Какие бафы нужны цели по типу «маг или воин» (`wanted`, `isCaster`, `needsBuff` с обновлением до конца). | Самобафы в 4b. Логика «не вешать магу Haste» пригодится и для пар в 4g. |
| LW `managers/PhantomWeaponSets.java` | Оружие для классов с несколькими типами оружия. Персонаж держит одно постоянное оружие. | Постоянное оружие персоны в 4e. |
| LW `taskmanagers/AutoPotionTaskManager.java` | Автобанки по порогам HP/MP/CP со списками id. | Идея порогов и id; у нас это решение мозга, а не глобальный таймер. |
| VP `systems/VirtualMageCombat.java` | Маг: не подпускает ближе 80 (`HARD_MIN_RANGE`), отходит (`moveAwayFromTarget`), подходит на дистанцию каста, садится реген по порогам MP (`shouldSitRegen`: сесть ниже X %, встать выше Y %, не садиться при угрозе рядом). | Пороги и логика отхода — в 4a (отдых и кайт). |
| VP `systems/VirtualSkillController.java` | Порог хила (`healHpThreshold`), поиск пропавшего бафа (`findMissingBuff`), хил с учётом раненых. | Хилеры и саппорты в 4b/4c. |
| VP `systems/VirtualSpoilController.java` | Spoil (не повторять на уже заспойленном), Sweep после смерти моба. | Спойлеры в 4c. |
| VP `systems/VirtualTankCombat.java` | Aggression / Aura of Hate по паку. | Танки в 4c, без раидовой части. |
| VP `systems/VirtualPvpDefense.java` | Защита при нападении игрока. | Уже есть своя версия (`PvpFightBack`, 3f); сверю пороги. |

**Что не берём:** весь VP построен вокруг пати и «следования за лидером» (`FollowLeaderState`, `AssistFarmState`, `VirtualParty`), с захардкоженными id и конфигами `VirtualPlayers.ini`. LW — это огромные менеджеры (`PhantomManager` ~8 тыс. строк, `PhantomPartyManager` ~8,4 тыс.). Берём **правила, данные и пороги**, а не классы целиком: у нас мозг работает через API ботов, а не через `Player`. Лицензии совместимы (LW — GPLv3, как и Mobius и наш репозиторий); авторство отмечу в шапках файлов.

## 2. Шаги этапа 4

### 4a — Выживание, боевое API и кайт (≈ 5–6 дней) → мини-проверка

| Что | Как это выглядит в игре |
|---|---|
| **Расширенное API скиллов и состояния.** `SkillView` получает тип (удар / нюк / баф / хил / дебаф / контроль / стойка), элемент, AoE или одиночный, цель, слот эффекта и флаг «можно сейчас». `SelfView` получает свои эффекты (бафы и дебафы с оставшимся временем), CP, число банок, стрел и зарядов. `NpcView` получает слабость моба к элементу (по пассивным скиллам NPC). | — (фундамент для 4b–4c; без него «умный бой» невозможен) |
| **Банки.** Бот пьёт HP-банку ниже порога (у каждой персоны свой, ≈ 40–60 %), CP-банки в PvP, у магов — восстановление MP по правилам класса. Откат банки соблюдается. Банки, как и сосками в КТ4, выдаются при появлении по уровню; настоящая закупка будет в этапе 5 (экономика). | Видно анимацию и эффект банки; бот «тянет» бой, а не падает. |
| **Отход и бегство от смерти.** Если HP низко, а банок нет или моб явно сильнее (несколько мобов, большая разница уровней), бот отходит из боя, а при погоне читает Scroll of Escape. Бот не берёт новых мобов, пока не восстановился. | Меньше трупов на споте. Бот, которому плохо, уходит, как живой. |
| **Отдых по порогам.** Сесть ниже X % HP/MP, встать выше Y % (пороги из VP), не садиться, если рядом агрессивные мобы. Восстанавливающие скиллы класса — только сидя и в безопасности (LW `ClassRecovery`). В городах по-прежнему не сидят. | Ритм «бой → бой → посидел» вместо бесконечного боя или сидения. |
| **Не перетягивать.** Бот оценивает пак (агрессивные рядом, их уровень) и не лезет в толпу сверх сил. | Меньше нелепых смертей на агрессивных спотах (Field of Silence). |
| **Кайт лучников и магов от мобов** (новое требование Глеба, перенесено из 4c). Лучник (лук в руках) и маг (есть нюк и MP) против моба ближнего боя: когда моб подошёл на дистанцию своего удара + 120, бот отходит назад на 400 (лучник — не дальше дальности лука − 50) и снова стреляет или кастует. Точка отхода — веер LW `PhantomCasterPositioning` (0/±30/±60°, проходимость и видимость по геодате), пороги — VP `VirtualMageCombat` (не ближе 80). Отход не чаще раза в 2 с; если моб быстрее и догоняет два раза подряд, кайт против него выключается до конца боя («кайт не работает»). Настройка `KiteDistance`. | Лучник и маг отступают от моба, пока тот замахивается, и бьют издалека — получают заметно меньше урона. Против быстрых мобов не дёргаются впустую. |
| **Метрика смертей в час** в строке `BOTS`. | По ней видно, что 4a сработало. |

**LOD:** всё перечисленное работает в ACTIVE. В PRESENT упрощённо: пороги банок и отдыха те же, без оценки пака.

**Мини-проверка перед КТ7 (после 4a):** пересобранный solo; Глеб смотрит в клиенте, как лучники и маги кайтят мобов, пьют банки и уходят из проигранного боя.

### 4c — Бой по ролям (≈ 8–10 дней) → **КТ7**

Движок плейстайлов: каждый боевой тик он проходит по списку класса и применяет первую строку, условия которой выполнены. Если ни одна не подошла — запасной выбор по LW `FallbackRules`, затем обычный удар. Скиллы, которые сервер отказал применить, временно отключаются (это уже есть с КТ4). Данные: `data/playstyles.xml` на все классы Interlude (стартовые, 1-я и 2-я профессии), с проверкой id скиллов по CT0 тестом данных.

| Роль | Поведение | Как это выглядит в игре |
|---|---|---|
| **Воины / танки** (Gladiator, Warlord, Destroyer, Paladin, DA, TK, ShK…) | Опенер, ротация ударов, стойки, заряды (накопить → потратить), PANIC-скиллы при низком HP. Танки — Aggression на пак. | Бой со скиллами, а не автоатака; гладиатор копит заряды. |
| **Лучники** (Hawkeye, Silver Ranger, Phantom Ranger) | Базовый кайт уже есть с 4a; в 4c — скиллы лучника по плейстайлу и дистанция по классу. Стрелы выдаются по грейду. | Лучник «кайтит», а не стоит в мобе. |
| **Маги** (Sorcerer, Necro, Spellsinger, Spellhowler) | Выбор нюка по слабости моба к элементу (если она есть), иначе самый сильный; дебафы только на «толстые» цели (`DURABLE_TARGET`, `DEBUFF_MISSING`); отход при сближении (кайт с 4a); сон/корни для отхода, где есть у класса. | Маг бьёт водой по огненным, отходит от моба, не стоит в мили. |
| **Хилеры / саппорты** (Bishop, Elder, Shillien Elder, Prophet, Warcryer, Overlord) | Соло, как живые: лечатся по порогу (VP `healHpThreshold`), держат свои бафы, бьют тем, что у класса есть (бишоп — святыми скиллами по нежити и т. п.). | Хилер не умирает молча — лечит себя. |
| **Кинжальщики** (Treasure Hunter, Plains Walker, Abyss Walker) | Заход со спины для blow-скиллов (`REAR`), опенер, Dash / Ultimate Evasion при опасности. | Кинжал обходит моба сзади. |
| **Спойлеры** (Bounty Hunter / Scavenger) | Spoil до убийства (не повторять, `NOT_SPOILED`), Sweep после. Полученное, как и весь дроп ботов, исчезает. | Видна анимация спойла и свипа. |
| **Саммонеры** (Warlock, Elemental Summoner, Phantom Summoner) | Призвать пета, натравить его на цель, бить вместе с ним; пет исчезает при уходе бота. Решено: настоящие петы. | У саммонеров есть петы. |

**LOD:** роли включаются только в ACTIVE. В PRESENT бот дерётся простой схемой «удар или нюк», как сейчас.

**КТ7 — проверка Глебом в клиенте (после 4a–4c):**
1. Постой 10–15 минут на охотничьем месте своего уровня рядом с ботами разных классов. Лучник отходит и стреляет, маг не стоит в мобе и отходит, кинжальщик заходит сзади, воин бьёт скиллами, у гладиатора копятся заряды.
2. Боты пьют банки при низком HP и отходят, когда плохо. Трупов заметно меньше, чем на КТ4–КТ5 (видно и по метрике `deaths` в логе).
3. На ботах видны бафы и стойки; у части новичков — бафы Newbie Helper.
4. Спойлер спойлит и свипает, саммонер воюет с петом.
5. `//bots info <ник>` показывает, какой плейстайл и какую строку бот применил и почему.

### 4g — Пары ботов (≈ 1–2 дня; решено: делаем)

Дешёвая версия «пати»: 10–15 % охотников появляются вдвоём или втроём (настоящая пати Mobius, без чата). ## 5. Риски

- **Данные плейстайлов.** Файл LW есть (39 плейстайлов, 241 скилл), но его надо сверить с CT0: тест данных ловит несуществующие id; недостающие классы допишем сами (+1–2 дня к 4c).
- **Слабость мобов к элементам** в Interlude задана пассивными скиллами NPC и есть не у всех мобов. Где её нет, маг просто бьёт самым сильным нюком.
- **Саммонеры** — самая хрупкая часть (пет — отдельный объект, его надо убирать при уходе бота). Если не взлетит, саммонеры временно бьют как маги.
- **Кайт по геодате** на сложном рельефе может «застревать». Страховка — проверка «8 с без продвижения» из КТ4 и отказ от кайта.
- **Нагрузка:** ACTIVE-ботов немного (они только рядом с игроком). Время тика контролируем метриками `p50/p99`; при перегрузе остаётся защита из 3f.
- **Объём 4c** может расти. Держу таймбокс: сначала по 1–2 класса на роль до КТ7, остальные плейстайлы — по мере твоих замечаний.
